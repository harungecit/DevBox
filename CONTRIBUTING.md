# Contributing to DevBox

Thanks for your interest in DevBox! Bug reports, feature ideas and pull requests are all welcome.

## Getting set up

Prerequisites:

- **Go 1.24+**
- **Node.js 20+**
- **Wails CLI v2.11** — `go install github.com/wailsapp/wails/v2/cmd/wails@v2.11.0`
- Windows only: **NSIS** if you want to build the installer (`wails build -nsis`)

```bash
git clone https://github.com/harungecit/DevBox.git
cd DevBox
wails dev          # run with hot reload (Go backend + Vite frontend)
```

Useful commands:

```bash
wails build                  # production build for your OS
go build ./...               # backend compile check (no Wails CLI needed)
go vet ./...                 # static analysis
go test ./... -count=1       # backend tests
cd frontend && npm run check # Svelte/TypeScript type checking
```

Architecture notes — package layout, IPC patterns, the platform abstraction, event names — live in [`CLAUDE.md`](CLAUDE.md). Please read the section relevant to your change before diving in.

## Ground rules

- **Cross-platform:** anything touching OS behavior goes through `internal/platform/` — never raw `syscall`/registry/shell calls in feature code. Before opening a PR, make sure all three targets still compile:
  ```bash
  GOOS=windows go build ./...
  GOOS=darwin  go build ./...
  ```
- **i18n:** every user-visible string needs a key in **both** `internal/i18n/locales/en.json` and `tr.json`.
- **Tests:** platform-dependent tests must skip gracefully on unsupported OSes (CI runs the test suite on Linux).
- **Generated code:** never edit `frontend/wailsjs/` by hand — it is regenerated by `wails dev` / `wails generate module`.

## Commit & PR conventions

- Commit messages: `area: short imperative summary` (e.g. `services: pick a free port on import`). Explain the *why* in the body when it isn't obvious.
- Keep PRs focused — one topic per PR.
- Fill in the PR template checklist; CI (vet, tests, cross-compile, svelte-check, Windows build) must be green.

## Reporting bugs / requesting features

Please use the issue templates. For anything security-sensitive, follow [`SECURITY.md`](SECURITY.md) instead of opening a public issue.
