# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is DevBox

DevBox is a cross-platform (Windows + macOS) desktop application for managing development runtimes (Go, Node.js, PHP, Python, Rust) and services (Nginx, Apache, Caddy, PostgreSQL, MySQL, MariaDB, MongoDB, Redis, Valkey, Mailpit). Built with Wails v2 (Go backend + Svelte/TypeScript frontend). Author: Harun Geçit.

## Commit rules

- **Never add `Co-Authored-By:` or `Claude-Session:` trailers to commits.** Plain commit messages only — the author wants a clean history under their own name.

## Development Commands

```bash
wails dev          # Run in dev mode (Go backend + Vite HMR frontend)
wails build        # Build production executable for current OS
wails build --nsis # Build with NSIS Windows installer (Windows only)
```

Frontend-only (from `frontend/` directory):
```bash
npm run dev        # Vite dev server only
npm run build      # Production frontend build
npm run check      # Svelte/TypeScript type checking
```

Build verification (no Wails CLI needed):
```bash
go build ./...     # Verify Go compilation for current OS
GOOS=darwin go build ./...   # Cross-check macOS build from Windows (and vice versa)
```

## Architecture

**Wails v2 desktop app**: Go backend exposes methods via IPC that the Svelte frontend calls through auto-generated bindings in `frontend/wailsjs/`. The frontend is embedded into the binary at compile time via `//go:embed all:frontend/dist`.

### Backend (Go 1.24)

- **`main.go`** — Only contains the `//go:embed all:frontend/dist` declaration. Shared by all OSes.
- **`main_windows.go` / `main_darwin.go`** — Build-tagged entry points. Each defines `func main()` with OS-specific Wails options (Windows: `windows.Options{Theme: Dark}`; macOS: `mac.Options{TitleBar: HiddenInset}`). Adding a third OS = add another `main_<os>.go`.
- **`app.go`** — Central `App` struct: the **only** Wails-bound struct, so all IPC methods live here. Startup initializes config → i18n → runtime managers → service managers → vhost regeneration → auto-start services.
- **`internal/platform/`** — **OS abstraction layer.** Defines the `Platform` interface (process attrs, PATH management, hosts file with elevation, autostart, open folder/file, binary/script naming, lib extension). `platform_windows.go` and `platform_darwin.go` each have `init()` that sets `current`. Package-level convenience functions (`platform.SetProcessAttrs`, `platform.AddToPath`, etc.) delegate to `current`. **Any new code that touches OS-specific behavior must go through this interface, not raw `syscall` / registry / `os/exec` shell calls.**
- **`internal/runtime/`** — Runtime version managers. Each implements `RuntimeManager` interface, registered in `manager.go:InitAll()`. Installs to `~/.devbox/runtimes/{name}/{version}/`.
- **`internal/service/`** — Service managers. Each implements `ServiceManager` interface, registered in `manager.go:InitAll()`. Installs to `~/.devbox/services/{name}/`. Only web servers form a **conflict group** (nginx/apache/caddy — vhost generation assumes a single active web server); databases and caches (MySQL + MariaDB, Redis + Valkey) can be installed side by side on different ports — install/import auto-picks a free port.
- **`internal/project/`** — Project management: scaffold, clone, domain/hosts, vhost generation, dev servers, SSL via mkcert, Cloudflare tunnels.
- **`internal/config/`** — Singleton config at `~/.devbox/config.json` with `sync.RWMutex`. Loaded once via `sync.Once`.
- **`internal/pathenv/`** — Thin wrapper over `platform` for PATH operations (Windows: registry `HKCU\Environment\Path` + `WM_SETTINGCHANGE`; macOS: `~/.devbox/path.sh` sourced from `~/.zshrc`).
- **`internal/i18n/`** — Translations via `//go:embed locales/*.json`. Flat key-value maps (`section.key` convention).

### Frontend (Svelte 3 + TypeScript + Tailwind CSS)

- **Routing**: No router library. `currentPage` writable store + `<svelte:component this={pages[$currentPage]}>` in `App.svelte`.
- **`frontend/src/pages/`** — Dashboard, Runtimes, Services, Projects, Path, Settings.
- **`frontend/src/lib/components/`** — Sidebar, ProgressBar, StatusBadge, ServiceInfoPanel, VersionPicker.
- **`frontend/src/lib/stores/app.ts`** — `currentPage`, `theme`, `appConfig` stores.
- **`frontend/src/lib/i18n/`** — `t` is a derived store returning a function: use `$t('key')` in templates. Language change triggers reactive update of all translated strings.
- **`frontend/src/lib/components/logos.ts`** — SVG logos imported as raw strings (`?raw`), sanitized with unique prefixes per icon to prevent DOM ID/class collisions.
- **`frontend/wailsjs/`** — Auto-generated by `wails dev`/`wails build`. **DO NOT EDIT.** Adding a new method to `App` struct requires re-running `wails dev` (or `wails generate module`, which only regenerates bindings without launching the app) for bindings to regenerate.
- **Svelte 3 markup cannot contain TypeScript** — no `as` casts inside `on:click={...}` handlers in templates; put casts in `<script>` helpers (`selectValue`, `inputValue`).

### Key Patterns

**Async installation flow** — All installs (runtimes, services, scaffolds, clones) are fire-and-forget goroutines. The IPC method returns immediately (`return nil`). Progress is reported via Wails events:
```
Frontend calls IPC method → app.go goroutine A creates buffered progress chan(10)
→ goroutine B runs Install(), sends Progress structs to chan
→ goroutine A drains chan, emits "runtime:progress" / "service:progress" events
→ on completion: emits "runtime:installed" / "runtime:error"
→ Frontend: EventsOn("runtime:progress", callback) in onMount, EventsOff in onDestroy
```

**Event names**: `runtime:progress/installed/error` (`runtime:installed` carries `updatedFrom` after an in-place update), `service:progress/installed/error` (also used by `UpdateService`), `services:changed` (tray start/stop-all, autostart), `versions:refreshed`, `scaffold:progress/complete/error`, `clone:progress/complete/error`, `devserver:started/stopped/error` (`stopped` carries `crashed`), `project:warning` (i18n `key`+`args` from provisioning), `composer:progress/installed/error`, `bun:installed/error`, `yarn|pnpm:installed/error`, `npm:updated/error`.

**Plugin registry** — Both `runtime.Registry` and `service.Registry` are `map[string]Manager` populated at startup by `InitAll()`. New runtimes/services implement the interface and add a `Register()` call in `InitAll()`.

**Process management** (`internal/service/process.go`) — Uses `platform.SetProcessAttrs(cmd, createGroup, hide)`, `platform.IsProcessRunning(pid)` and `platform.KillProcessTree(pid)` (Windows `taskkill /T /F`, macOS process group) — every Stop path (services, dev servers, front-door, Adminer, devtools) kills the whole tree, because npm `.cmd` shims and nginx/apache masters otherwise leave orphans holding the port. npm-based web tools are additionally launched as `node <bin script>` rather than through the shim so the same code works on Windows (CREATE_NEW_PROCESS_GROUP + hidden window, `OpenProcess`+`GetExitCodeProcess==259`) and macOS (`Setpgid`, `kill -0`). PID files at `~/.devbox/services/{name}.pid`. The same PID+process pattern is reused in `project/devserver.go`, `runtime/php_cgi.go`, `tunnel/cloudflared.go`.

**Binary/script naming** — Use `platform.BinaryName("go")` (→ `go.exe` on Windows, `go` on macOS) and `platform.ScriptName("npx")` (→ `npx.cmd` / `npx`) when constructing executable paths inside runtime/service managers. Never hard-code `.exe` / `.cmd` / `.dll`.

**Vhost generation** — `internal/project/vhost.go` generates configs for nginx/apache/caddy per project. App-server frameworks get `proxy_pass`; PHP/static frameworks get FastCGI to `127.0.0.1:9000`. `regenerateAllVhosts()` in `app.go` runs on startup and after port/domain changes, then restarts the web server.

**Hosts file** — `internal/project/hosts.go` delegates to `platform.WriteHostsFileElevated()`: Windows uses `ShellExecuteExW` with `runas` verb (UAC) to copy a temp file to `C:\Windows\System32\drivers\etc\hosts`; macOS uses `osascript` with `administrator privileges` to copy into `/etc/hosts`. Entries tagged with `# DevBox managed`.

**Global version** — Active runtime version stored in `config.ActiveRuntimes[name]`, not symlinks. `pathenv.AddToPath(mgr.BinaryPath(version))` updates the OS-specific PATH (registry on Windows, `~/.devbox/path.sh` on macOS).

**All data under the DevBox data dir** — `platform.DefaultDataDir()`: `C:\DevBox` on Windows (`%SystemDrive%\DevBox`), `~/DevBox` on macOS. Never hard-code `~/.devbox`; always go through `config.GetDataDir()`. Contents: runtimes, services, projects (default home for scaffolded/cloned projects), config.json, logs, tmp, cache (remote version lists), ssl/certs, projects.json, tunnel-routes.json, backups, and on macOS `path.sh`.

**Legacy migration** (`internal/config/migrate.go`) — first launch after the move: stops every process left from the old tree (via *.pid files, `nginx -s quit`, `mysqladmin shutdown`), renames `~/.devbox` → new dir (copy fallback), rewrites embedded absolute paths in service configs / php.ini / proxy Caddyfile (all three spellings: `\`, `/`, `\\`), re-points managed user PATH entries. Logged to `<data>/logs/migration.log`; `config.Migrated` lets the Settings page show a one-time notice. Unit-tested in `migrate_test.go`.

**Remote version cache** — `runtime/cache.go` and `service/updates.go` persist fetched version lists under `<data>/cache/` with a TTL (`config.VersionCacheHours`, default 48h). `GetRemoteVersionsInfo(name, force)` / `GetServiceVersions` serve from cache; `app.versionRefreshLoop` refreshes stale caches 4s after launch and every 6h, then emits `versions:refreshed`. Pages must read caches (never scrape on open) and listen for that event.

**In-place updates** — `runtime.UpdateLine(name, ver)` defines the release line inside which a newer version is an *update* (node/rust: major; go/php/python: major.minor). `RuntimeVersionInfo.UpdateFor` marks remote versions that replace an installed one; `App.UpdateRuntime(name, from, to)` installs, runs `runtime.MigrateVersionData` (php.ini, yarn/pnpm + global npm packages, pip packages), moves global/PATH/project pins, then uninstalls `from`. Services: `service.CheckUpdate` fills `ServiceInfo.UpdateVersion` (same-major only for postgres/mysql/mariadb/mongodb — their data format is major-bound; `LatestMajor` is informational) and `service.Update` reinstalls while stashing `preservedPaths(name)` (data dirs, generated configs, vhosts).

**PHP FastCGI, one instance per version** (`runtime/php_cgi.go`) — the globally active PHP listens on 9000; a project pinned to another version gets its own php-cgi on a port from `config.PhpCgiPorts` (9001+). State files: `services/php-cgi-<version>.pid` ("pid\nport"). `regenerateAllVhosts()` computes the versions domain-bound PHP projects need via `project.ResolveRuntimeVersion`, calls `runtime.EnsurePHPCGI` to reconcile instances, and hands each vhost the right port (nginx `fastcgi_pass`, caddy `php_fastcgi`, apache `SetHandler proxy:fcgi://` — `patchConfig` enables mod_proxy_fcgi/rewrite and includes `conf/extra/vhost-*.conf`). Dev servers likewise run under the pinned version: `project.ResolveRuntimeBinDir` is prepended to the child PATH and the executable is resolved there.

**Tray & lifecycle** — `github.com/energye/systray` via `RunWithExternalLoop` (`tray_windows.go`, `tray_darwin.go` (cgo), `tray_darwin_nocgo.go` stub so `GOOS=darwin go build` from Windows stays green, shared menu in `tray_menu.go`). `App.beforeClose` hides the window when `config.CloseToTray` (default on); services keep running until tray → Quit (`App.quit` sets `quitting`). `main.startHidden()` honours `--minimized` (`platform.AutoStartFlag`, appended to the login entry by `SetAutoStart`) and `config.StartMinimized`. `SingleInstanceLock` re-shows the window on a second launch. `startup` re-registers the login entry when `cfg.AutoStart` so an installer upgrade can't leave a stale exe path.

**PHP extensions** — `runtime/php_extensions.go` lists every DLL in `ext/` (ini-listed or not); opcache/xdebug are `zend_extension=` (`zendExtensions` map — `TogglePHPExtension` normalises the directive). `runtime/php_pecl.go` installs prebuilt PECL DLLs for Windows: scrapes `windows.php.net/downloads/pecl/releases/<ext>/<ver>/` for `php_<ext>-<ver>-<php.line>-nts-vs*-x64.zip` (Xdebug from xdebug.org), puts `php_<ext>.dll` in `ext/` and helper DLLs (ImageMagick) next to `php.exe`, records installs in `ext/devbox-pecl.json`. Events `phpext:progress/installed/error`.

**App updates & releases** — `internal/updater` reads `api.github.com/repos/harungecit/DevBox/releases/latest`; `updater.Version` is injected with `-ldflags "-X DevBox/internal/updater.Version=x.y.z"` (default `0.0.0-dev`). Assets are matched by name: `DevBox-Setup-<ver>-windows-amd64.exe`. `.github/workflows/release.yml` builds on `v*.*.*` tags (test → wails build -nsis → optional Authenticode signing via `WINDOWS_CERT_PFX_BASE64`/`WINDOWS_CERT_PASSWORD` → checksums → GitHub Release); `ci.yml` runs vet/test/cross-compile/svelte-check/windows build; `website.yml` deploys `docs/` (static TR/EN site, privacy, terms) to Cloudflare Pages at devbox.harungecit.dev (secrets: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN).

**Framework catalog** (`internal/project/frameworks.go`) — `Catalog` is the ordered registry of everything DevBox recognises (detection rule, runtime, app-server flag, default port, start command). `DetectFramework`, `RuntimeFromFramework`, `IsAppServer`, `DefaultPort`, `GetStartCommand` all read it; specific entries must precede generic ones (Laravel → PHP, Next.js → Vite → Node). The frontend loads it via `GetFrameworkCatalog` (its static lists are only a fallback). Adding a framework = one catalog entry (+ colour in `frameworkColor`, + optional scaffold template in `scaffold.go`; `scaffold_starters.go` holds file-based starters for generators that are interactive). Tests: `frameworks_test.go`.

**Editable connection settings** (`service/settings.go`) — the info panel's rows carry a `Key` (`port|user|password|databases`); `App.SetServiceSetting` routes `port` to `SetServicePort` and the rest to `service.SetSetting`, which really applies them: PostgreSQL `ALTER ROLE` via `psql` (+ `CREATE ROLE` for a new user) and rewrites `pg_hba.conf` loopback rules trust ⇄ scram-sha-256 then restarts; MySQL/MariaDB `CREATE USER IF NOT EXISTS`/`ALTER USER` for `localhost` + `127.0.0.1` via the client with `MYSQL_PWD`; Redis/Valkey `requirepass`/`databases` through `redisExtraConfig` in `writeConfig` + restart. Values persist in `devbox-service.json` (`User`, `Password`, `Databases`); `service.Credentials(name)` is the single source for display strings, `mysqladmin shutdown` and Redis Commander. Redis/Valkey Windows builds are MSYS-based and cannot take `C:\` paths — config/data paths are passed relative to the service dir.

**Terminal integration** (`internal/terminal`, `app_terminal.go`) — DevBox never embeds a terminal; it opens the user's (Windows: Windows Terminal → PowerShell 7 → Git Bash (mintty + `bash --rcfile`) → Cmder/ConEmu → Windows PowerShell → cmd; macOS: iTerm2 → Terminal via osascript + a ZDOTDIR that sources `~/.zshrc` first) with a generated init script under `<data>/tmp/terminal/` (PATH prepend, env, `cd`, prompt tag `devbox:<title>`, optional first command). `config.Terminal` = preferred id, Settings picks it. `OpenTerminal` (all global runtimes + tools on PATH, Dashboard button + tray), `OpenProjectTerminal` (pinned runtime first, `PORT`/`DEVBOX_*`), `OpenServiceTerminal` (starts the service if needed, runs `psql`/`mysql`/`redis-cli`/`mongosh` connected with credentials in env). Scripts go through a file so Windows Terminal's single-instance hand-off keeps the environment.

**Developer tools catalog** (`internal/devtools`) — `Catalog` lists optional tools by `Kind`: `pip` (into the active Python; console scripts in `Scripts/`), `go` (`go install` with `GOBIN=<data>/tools/gobin`), `cargo` (`cargo install --root <data>/tools/cargo`), `binary` (GitHub asset → `<data>/tools/<id>/`, e.g. uv), `npm` (web UIs: `npm i -g --prefix <data>/tools/<id>`, run against the first installed service in `ForServices`, PID file `tools/<id>.pid`, fixed ports 8506 Redis Commander / 8507 mongo-express; Adminer keeps 8505). One generic flow: `GetDevTools`/`InstallDevTool` (events `devtool:progress/installed/error`)/`UninstallDevTool`/`OpenDevTool`/`StopDevTool`; bin dirs are added to PATH after install; `StopAll` on quit. UI: `DevToolRow.svelte` rendered per group on the Tools page (`desc` is an i18n key).

**Composer** (`runtime/composer.go`) — lives in `<data>/tools/composer` (on PATH), not inside a PHP version dir, so switching the global PHP never loses it: `composer.phar` for a DevBox download, or `devbox-composer.json` (`{"phar": ...}`) for a system Composer imported in place; the `composer.bat`/`composer` wrapper runs `php <phar>` with whatever php is first on PATH. `MigrateLegacyComposer` (startup) moves a phar older builds kept under `runtimes/php/<ver>/`. `GetComposerInfo` compares the installed version with getcomposer.org/versions `stable[0]` (cached in `cache/composer-latest.json`, TTL `CacheTTL`); `UpdateComposer` runs `self-update --stable` (managed *and* imported phars; a managed one that fails is re-downloaded). Discovery: `discovery.ScanTools` (Found.Kind `tool`) resolves PATH wrappers and well-known locations (Composer-Setup, Laragon, XAMPP, scoop, Homebrew) to the phar; `App.ImportExternalTool` links it. Events `composer:progress/installed/updated/error`.

**Front-door proxy & HTTPS** (`internal/proxy`) — bundled Caddy 2.9 on :80/:443 (`ProxyEnabled`, off until the user or `provisionProject` starts it — dev-server projects need it to have a domain at all). `renderCaddyfile` writes one `http://` block per project (tunnel traffic carrying `X-Forwarded-Proto: https`/`Cf-Visitor` is proxied, plain hits `308`-redirect when SSL is on) and one `https://` block using the project's mkcert files (`project.CertPaths`), forwarding `X-Forwarded-Proto: https`; a `handle_errors 502-504` heredoc page tells the user the backend is stopped. While `proxy.TLSAtFrontDoor()` (installed + enabled) is true, `GenerateNginxVhost` omits its own `listen 443` block so the two never fight over the port; `StartProxy`/`StopProxy` regenerate vhosts around the toggle for the same reason. `caddyfile_test.go` validates the output with the bundled `caddy.exe` when present.

**Dev-server watchdog** (`project.OnDevServerExit`, `App.onDevServerExit`) — every dev server exit emits `devserver:stopped {crashed, log}`; `Project.AutoStart` ("keep alive", `SetProjectAutoStart`) starts the server at launch (`autoStartDevServers`) and restarts a crash after 2s, at most 3 times per 5 minutes, then emits `devserver:error`. `StopDevServer` marks `stopping[name]` so intentional stops aren't restarted.

**Cloudflare named tunnels** (`tunnel/cloudflare_api.go`, `tunnel/named.go`) — optional: Settings verifies an API token (Account·Cloudflare Tunnel·Edit, Zone·DNS·Edit, Zone·Zone·Read), picks account + zone, `ConfigureCloudflare` creates/reuses one remotely-managed tunnel per machine (`devbox-<hostname>`). A project with `PublicHostname` set shares through it: `StartNamedTunnel` pushes the ingress rule (origin = front-door or webserver port, `httpHostHeader` = local domain), ensures a proxied CNAME, and runs a single `cloudflared tunnel run --token` connector (`services/cloudflared-named.pid`). Routes persist in `tunnel-routes.json` and resume at startup. Projects without a hostname keep using quick tunnels.

## i18n

Two languages: English (`en`) and Turkish (`tr`). Backend embeds JSON from `internal/i18n/locales/`. Frontend receives entire translation map via `GetLocale(lang)` IPC call. Keys use `section.key` format (e.g., `nav.dashboard`). Template variables use `{0}`, `{1}` positional syntax — substitution happens on the frontend. **When adding UI text, add keys to both `en.json` and `tr.json`.**

## Platform-Specific Details

All listed here is encapsulated in `internal/platform/` — touching it usually means editing both `platform_windows.go` and `platform_darwin.go`.

**Windows**
- PATH stored in registry `HKCU\Environment\Path`, broadcast via `WM_SETTINGCHANGE` (`SendMessageTimeoutW`)
- WebView2 for rendering (installed via NSIS if missing)
- UAC elevation via `ShellExecuteExW` with `runas` verb for hosts file writes
- `CREATE_NEW_PROCESS_GROUP` + `HideWindow` for child processes
- Auto-start via `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- NSIS installer config in `build/windows/installer/project.nsi`
- Build assets in `build/windows/` (`icon.ico`, `wails.exe.manifest`)

**macOS**
- PATH stored in `~/.devbox/path.sh`, sourced from `~/.zshrc` (one-time append by `ensureShellSource`)
- WKWebView for rendering (system-provided)
- Admin elevation via `osascript … with administrator privileges` for hosts file writes
- `Setpgid` for child processes; `kill(pid, 0)` for liveness check
- Auto-start via `~/Library/LaunchAgents/com.devbox.app.plist` (LaunchAgent)
- Build assets in `build/darwin/` (`Info.plist`, `Info.dev.plist`)
